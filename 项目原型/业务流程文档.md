## 1. 系统概述

### 1.1 系统定位

**课程项目：LLM对话平台用户行为分析系统**

本项目分为两个部分：
1. **对话平台**：用户与LLM对话界面，用于用户与LLM的对话
2. **管理后台（核心）**：采集行为数据，展示用户旅程图和体验分析

**核心问题**：如何分析和可视化用户在LLM对话平台上的使用体验？

**解决方案**：通过模拟用户的行为，采集数据后通过管理后台构建用户旅程图，展示多轮对话中的体验指标。

### 1.2 系统组成

### 1.3 对话模拟器 vs 管理后台

| 对比项 | 对话模拟器 | 管理后台 |
|--------|-----------|----------|
| 定位 | 大作业展示界面 | 核心产品 |
| 用户 | 演示用/评委 | 项目团队自己 |
| 优先级 | 视觉效果 | 功能完整 |
| 数据流 | 产生数据上报 | 接收数据展示 |
| 复杂度 | 中（界面美观） | 高（分析功能） |

### 1.4 核心价值

| 价值点 | 说明 |
|--------|------|
| 行为数据采集 | 自动采集模拟用户在对话过程中的交互行为 |
| 旅程图可视化 | 将用户操作串联成时间线，直观展示 |
| 体验指标分析 | 分析多轮对话的深度、流失、响应时间等 |

## 3. 后台数据处理流程

### 3.1 行为数据采集流程

```
┌─────────────────────────────────────────────────────────────┐
│                    用户在对话平台的交互                       │
│                                                             │
│  - 页面加载 (PAGE_LOAD)                                     │
│  - 发送提问 (LLM_QUERY)                                      │
│  - 收到响应 (LLM_RESPONSE)                                   │
│  - 点赞/点踩 (THUMBS_UP/DOWN)                                │
│  - 复制结果 (COPY_RESULT)                                    │
│  - 发生错误 (ERROR)                                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    自动采集                                  │
│                                                             │
│  自动采集：                                                  │
│  - Session ID 自动生成和管理                                │
│  - Turn ID 自动递增                                         │
│  - 页面加载、点击等事件自动采集                               │
│                                                             │
│  业务事件触发：                                              │
│  - LLM_QUERY: 用户点击发送时                                 │
│  - LLM_RESPONSE: 收到AI响应时                                │
│  - THUMBS_UP/DOWN: 用户点赞/点踩时                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    数据上报                                  │
│                                                             │
│  POST /api/v1/sdk/track                                     │
│  Body: { session_id, user_id, events: [...] }               │
│                                                             │
│  上报时机：                                                  │
│  - 批量上报                                                  │
│  - 页面关闭时                                               │
└─────────────────────────────────────────────────────────────┘
```

**采集字段**：

| 字段 | 说明 |
|------|------|
| session_id | 会话唯一ID |
| user_id | 用户ID |
| turn_id | 对话轮次 |
| event_type | 事件类型 |
| timestamp | 发生时间 |
| payload | 事件数据 |
| context | 上下文信息 |

### 3.2 事件清洗与脱敏流程

```
┌─────────────────────────────────────────────────────────────┐
│                    原始事件 (Raw Event)                     │
│  { session_id, user_id, event_type, payload, timestamp }    │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤1：格式校验                                             │
│  - 必填字段是否存在                                         │
│  - 事件类型是否在白名单                                      │
│  - 时间戳是否合理（当前时间±1天）                            │
└─────────────────────────────┬───────────────────────────────┘
                              │ 通过
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤2：PII脱敏                                              │
│  检测并替换敏感信息：                                        │
│  - 手机号 → [phone_redacted]                                │
│  - 邮箱 → [email_redacted]                                 │
│  - 身份证 → [idcard_redacted]                              │
│  - IP地址 → [ip_redacted]                                  │
└─────────────────────────────┬───────────────────────────────┘
                              │ 完成
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤3：事件去重                                             │
│  - 基于 event_id 去重                                      │
│  - 保留首次出现的记录                                       │
└─────────────────────────────┬───────────────────────────────┘
                              │ 完成
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 干净事件 (Clean Event)                                      │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 会话与旅程构建流程

```
┌─────────────────────────────────────────────────────────────┐
│ 查询条件：指定 session_id                                   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤1：收集该session的所有事件                              │
│  - 从事件存储中查询                                          │
│  - 按 timestamp 排序                                        │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤2：构建节点                                             │
│  每个事件转换为一个节点：                                    │
│  { id: "n1", event_type: "PAGE_LOAD", timestamp: ... }     │
│  { id: "n2", event_type: "LLM_QUERY", payload: {prompt} }  │
│  { id: "n3", event_type: "LLM_RESPONSE", payload: {...} }  │
│  { id: "n4", event_type: "ERROR", payload: {...} }        │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 步骤3：建立边关系                                           │
│  - 相邻事件：sequence 边（正常交互）                         │
│  - 时间间隔>30分钟：jump 边（长时间中断）                    │
│  - ERROR后：error 边                                        │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 旅程图输出                                                  │
│ { nodes: [...], edges: [...] }                              │
└─────────────────────────────────────────────────────────────┘
```

**旅程图示例**：

```
用户旅程：sess-abc123

[PAGE_LOAD] ──sequence── [LLM_QUERY] ──sequence── [LLM_RESPONSE]
                                   │
                              (用户追问)
                                   │
                                   ▼
                            [LLM_QUERY] ──sequence── [LLM_RESPONSE]
                                                     │
                                               (等待42秒)
                                               触发 ERROR
                                                     │
                                                     ▼
                                              [ERROR: Timeout]
                                                     │
                                                (用户离开)
                                                     │
                                                     ▼
                                               [terminal]
```

## 7. 术语说明

| 术语 | 说明 |
